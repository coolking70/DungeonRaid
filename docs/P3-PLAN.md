# P3 表现层规划：原版风格界面复原

- 目标：把现在的调试台换成原版风格的完整游戏界面，包括布局、屏幕流转、动画和音效。
- 美术、音效、字体全部使用原创或开源素材，公开版不含原版资源。
- 规则引擎（`src/core`）在 P3 中**不改动规则**。只有发现表现层确实需要、但引擎没有暴露的事件或字段时，才以「只增不改」的方式扩展，并且需要提供测试。

## 用户决定（2026-10-15）

| 事项 | 决定 |
| --- | --- |
| 美术 | 继续使用 Codex imagegen 生成原创重绘（同 A01），禁止把原版图片作为生成输入 |
| 语言 | 中英双语可切换，默认中文。英文直接用原版字符串，中文由 Codex 翻译。原版中烘焙在图里的标题文字，一律改为字体渲染 |
| 字体 | 使用 OFL 协议的像素字体（候选：Fusion Pixel / Ark Pixel），按实际用到的字做子集后随仓库分发 |
| 音效 | 用程序合成：sfxr 式参数加 WebAudio，按原版 39 个音效的触发点和类型原创设计。本地 dev 模式可以切换到原版 ogg 做对比 |
| 装备图标 | 约 80 个原创基础图，再用程序生成变体，填满原版 400 个图标槽位 |
| 参考截图 | 不搭模拟器。布局和动画只从原生代码里的坐标、尺寸、时序还原 |

## 原版界面概况

来自对 `reverse/` 的调研：

- **逻辑分辨率**：竖屏 320×480，GLES1 正交投影，以 `App::resize` 和 `DungeonRaidRenderer` 为准。
- **图集**：
  - `tiles.png`：棋盘格、HUD（资源条、药水瓶、护甲）、主菜单按钮、烘焙标题字；
  - `menus.png`：10 个职业图标、10 个种族头像、属性 / 优缺点图标、菜单框、确认对话框；
  - `icons.png`：400 个装备图标；
  - 三套位图字体：普通、菜单、分数。
- **屏幕与组件**（原生类）：
  - 主菜单：Continue / New Game / Tutorial / Scores / Challenge / Sound / High Scores；
  - `ClassScreen`：职业配置，含种族、优点、缺点、技能等标签页；
  - `Interface`：局内 HUD，包括资源条、生命和护甲、技能栏、提示框、心跳效果；
  - `FoldoutMenu`：升级、商店、强化菜单；
  - `HelpMenu`：教程和提示；
  - `ScoreScreen`：高分榜，分页显示；
  - 确认对话框、`Game::Render`（棋盘、连线、调暗）。
- **动画**：
  - `Token::Process`：资源飞向资源条；
  - `Particles`：碎裂、火花；
  - `Label`、`SimpleLabel`：飘字；
  - `AddFlare`：闪光；
  - 护盾碎裂（ProcessShieldShatter / Chunk）；
  - 心跳（ProcessHeartbeat）；
  - 调暗（UpdateDimming）；
  - 资源影子（ProcessResourceShadows）。
- **音效**：39 个，含 1–3 个随机变体，由 `QueueSound` 按 id 触发；`SoundEngine.java` 负责映射。

## 拆卡

```
U01 规格提取 ──┬── A02 界面美术 ──┐
              ├── A03 装备图标 ──┤
              ├── S01 音效合成 ──┼── U03 菜单与界面外屏幕 ─┐
              ├── L01 翻译与字体 ┤                        ├── U05 打磨与验收
              └── U02 渲染框架 ──┴── U04 局内 HUD 与动画 ──┘
```

| 卡 | 内容 | 产出 | 验收 |
| --- | --- | --- | --- |
| **U01** 规格提取 | 从原生代码中提取：每个屏幕的元素表（逻辑坐标、尺寸、图集区域、文字、触摸区域）、屏幕流转状态机、动画时序、音效触发表、全部界面字符串，以及美术需求清单 | `docs/spec/10–13`；`data/ui-layout.json`、`ui-strings.json`、`sounds.json` | 坐标和时序都有函数证据；字符串与原生字符串表逐条对照 |
| **A02** 界面美术 | HUD 框架、资源条、药水瓶 / 护甲、按钮、菜单面板、对话框、职业图标、种族头像、属性 / 优缺点 / 技能图标 | `art/ui.png` 及其清单 | 风格与 A01 统一；版权相似度自检；在逻辑尺寸下清晰可辨 |
| **A03** 装备图标 | 约 80 个基础图 + 程序变体，覆盖 400 个槽位 | `art/items.png` 及其清单 | 每个槽位非空；同类变体可区分；版权自检 |
| **S01** 音效合成 | 39 个音效的 sfxr 式参数和 WebAudio 合成器，包括随机变体 | `ui/audio/*`、`data/sfx.json` | 试听页；时长和响度统一；与触发表一一对应 |
| **L01** 翻译与字体 | 全部界面、技能、装备、敌人、成就文本的中文翻译；像素字体子集化 | `data/i18n/zh.json`、`en.json`；字体 woff2 | 覆盖率 100%；术语表一致；子集包含全部所需字形 |
| **U02** 渲染框架 | 320×480 逻辑画布按比例缩放；屏幕栈；图集精灵；补间与时间线（消费引擎事件）；音频管理；i18n；输入；`?debug` 时保留调试台 | `ui/` 重构 | 现有玩法不退化；60fps；手机触控 |
| **U03** 界面外屏幕 | 主菜单、职业配置、教程 / 帮助、高分榜与成就、设置、确认框 | | 截图对照规格逐项检查 |
| **U04** 局内界面 | HUD 布局、连线绘制、折叠菜单、全部局内动画与音效、提示框 | | 事件到动画全覆盖；整局试玩 |
| **U05** 打磨与验收 | 性能、移动端、可访问性（色弱、静音）、首次加载体积 | 发布 | 用户试玩 |

- **执行分工**：所有卡都由 Codex（gpt-6-astra）执行。U02–U04 可以使用 Codex 的 `develop-web-game` 技能做截图自检。Claude 负责验收：在浏览器内逐屏截图，对照规格，并完成整局试玩。
- **并行规则**：U01 完成后，A02、A03、S01、L01 写入的目录互不重叠，可以并行；U02 与这四张卡也可以并行。U03 和 U04 都依赖 U02，以及对应的美术和字符串。

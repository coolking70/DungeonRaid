# Dungeon Raid 重写 / 移植路线图

- 起点：Android 版 1.2.11 APK。逻辑全部在 32 位原生库 `libDungeonRaidJni.so` 里（C++，导出符号完整），Java 层只负责外壳、输入、音频和 GL 纹理。
- 目标：能在 64 位 Android 14–16 上运行，targetSdk ≥ 35，同时提供网页版。
- 背景：原版无法直接适配，原因见 `../APK分析报告.md`。

## 技术选型

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 规则引擎 | TypeScript 纯函数 + 种子 RNG | 可以用 Vitest 完整测试，便于和原版逐条对照 |
| 表现层 | Canvas 2D（Vite） | 原版是 2D 精灵加 GLES1 四边形，Canvas 足够 |
| Android 封装 | Capacitor | 产出 arm64 APK、高 targetSdk，没有原生 so 的包袱 |
| 美术 / 音效 | 先复用原版资源（仅个人使用） | 需要公开发布时，再走自己的像素素材产线替换 |

## 执行分工

- **Codex（gpt-6-astra）**：规格提取、规则引擎、数据表。这些都能用测试或证据在沙箱里自证。
- **Claude**：派发任务卡、验收（读 diff、重跑测试、抽查证据）、表现层联调和截图、Android 打包与模拟器验证。
- 派发方式见 `docs/WORKFLOW.md`。

## P2 技术决定（2026-10-15，用户确认）

- **忠实度选 B「数值忠实」**：
  - float32 一律经过 `Math.fround`；整数按 ARM 的截断规则；
  - 6 路 RNG 的算法和调用顺序与原版一致，以便 P6 用同一种子与原版逐回合对照；
  - 不复刻原版存档格式，也不复刻除零得到无穷大之类的边界行为。
- **core 形态**：
  - `src/core` 用 TypeScript strict 编写，没有运行时依赖，只用 Vitest 做测试；
  - 唯一入口是 `step(state, action) → { state, events }`，回合按阶段推进，可在中途暂停（例如奖励菜单）；
  - 内部按原版结构使用可变状态，只在 `step` 的边界复制一次。
- **数据**：通过带类型的加载层读取 `data/*.json`，不在代码里硬编码数值。
- **未决规格**：B1、B2、C2–C4、I1 等各做成一个具名开关，并给默认值。代码注释标出未决编号，留到 P6 用原版对照来裁定。
- **可追溯**：测试名里带上 07 用例编号（如 `C12`），验收时统计编号覆盖率。
- **依赖由 Claude 预先安装**：Codex 沙箱可能无法联网，所以 Claude 先装好依赖并提交 lockfile。
- **调试界面**：T04 完成后，Claude 先搭一个最简调试界面（原版贴图 + 鼠标拖线），让用户尽早上手试玩。

## 环境

与 T03 相同：依赖已经装好，**不要运行 `npm install`，也不要新增依赖**。命令是 `npm run check`。

## 目标

做完本卡后，引擎可以从 NewGame 开始，连续进行任意多个**只含普通敌人**的回合，直到死亡；Sprint 模式要能在第 100 回合胜利。这是 Claude 随后搭调试界面、让用户上手试玩的前提，所以端到端可玩是硬指标。

## 要做的事

1. **输入动作**：
   - 实现 `SelectTile` / `ExtendChain`、`Backtrack`（回退到链中某个旧格时，删除它之后的所有节点）、`CancelChain`、`CommitChain`。
   - 输入层只接收格子坐标，触点到格子的命中判定（中心圆半径 0.4 格）留给 UI 层。可以在 core 里导出一个纯函数供 UI 调用。
   - 连线合法性：同类判定（`CanMatchType`）、八方向邻接、有效长度至少 3（不计忽略格）、箭头格（arrow）的忽略逻辑。
2. **链的预览**：选择过程中持续计算链伤害 D、吸血、Spiky 反伤与火伤、资源预览，通过事件或状态字段暴露给 UI。拖线时实时显示「这一下会打死谁」靠的就是它。
3. **提交结算**：按 `02-chain-and-turn.md` 的「一次行动的主顺序」实现：
   - `MatchTiles` / `MatchTile`：剑和骷髅的伤害，即逐个敌人吃满 D、护甲与破甲、穿透、毒；
   - 盾修甲与溢出规则、药水治疗、金币；
   - token 入账：三条资源条的余数、累计值、进位、bonus 和额外 token；
   - 计数、击杀统计。
4. **资源条满**：只负责**排队并暂停**：
   - 把对应的菜单请求放进 `menus` 队列，`phase` 进入等待菜单；
   - 提供 `ChooseMenuOption` 动作的骨架，本卡里只需支持「跳过 / 确认」后继续结算，菜单的具体内容由 T06 实现；
   - 暂停和恢复后的结算顺序必须与规格一致。
5. **敌人回合与 EndOfTurn**：
   - 普通骷髅的攻击汇总（排除本回合新生成的格和冻结的格）、护甲吸收、护甲破损、每次攻击至少掉多少血（以规格为准，不要凭印象）；
   - 玩家中毒、再生；
   - 技能充能 +1（Mage 的判断可以先只看场上计数）；
   - 晋升计时、回合数 +1，以及 `EndOfTurn` 的严格顺序。
6. **下落补充与清理**：调用 T03 的 `moveMatchedTiles`，并在正确的阶段处理 `moving` 队列和 `newThisTurn` 标志。
7. **胜负**：死亡判定；Sprint 第 100 回合胜利；进入 `GameOver` 阶段，并产出最终状态事件。

## 端到端要求

增加 `test/playthrough.test.ts`：
- 用一个简单的确定性策略（例如每回合选第一条合法的最长链），对 3 个种子、四种难度各跑完整局，直到死亡，或最多 300 回合。
- 每一步检查不变量：
  - 36 格都有内容；
  - HP ≤ 上限；
  - 护甲在 0 和上限之间；
  - 资源条余数小于对应阈值；
  - `phase` 合法；
  - 没有未消费的悬挂 pending；
  - RNG 只通过显式路数调用。
- 同一种子跑两遍，最终状态的哈希必须一致。
- 遇到特殊敌人时，允许按 T03 的 `special-pending` 占位处理（例如当作普通敌人进入攻击汇总），但必须在报告里说明占位规则，并且该规则要能在 T05 中直接替换。

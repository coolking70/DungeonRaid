## 交付与来源边界

- `src/audio/synth.ts`：手写单声道采样合成器、运行时参数校验、`renderSamples()` 与 `synthesize()`（返回 AudioBuffer）。
- `src/audio/player.ts`：70 个 AudioBuffer 的预渲染缓存、显式变体选择、八路播放、音量/静音、手势解锁与生命周期清理。
- `data/sfx.json`：38 类、70 个变体的完整原创参数、音色说明及来源声明。
- `tools/sfx-preview/index.html`、`main.ts`、`vite.config.ts`：独立试听页，可逐变体播放、查看完整参数、顺序播放、停止、调音量、静音。
- `test/audio-synth.test.ts`：39 项合成器/播放器测试。

已阅读 AGENTS.md、P3-PLAN、12 号音效规格、sounds.json。设计只使用 `sounds.json` 的名称、时长、designDescription 与触发语义；**未读取任何原版 OGG，未试听、解码、分析或仿制其波形/频谱**。没有引入第三方音频文件、音频库或依赖，没有运行 npm install，没有 commit。未修改 reverse/、原 APK 或其他执行者的文件。

P3 规划中的“39”是概数；本交付依照 12 号规格的 **38 类、70 变体**，包括 heartbeat 的四变体。依据：`Sound.java SOUND_COUNT=38`、`GetSoundName @0x6770c`、`GetSoundVariations @0x678c4` / 表 `0x6e390`，均沿用 U01 的 `data/sounds.json` 记录。

## 合成设计与参数

所有音高、包络、音符排列、滤波参数、噪声种子均为本卡原创选择，不是逆向结论。

- 波形为 sine / square / saw / noise；方波和锯齿用 PolyBLEP 减轻跳变混叠。多层混合实现金属泛音、双心跳、碎片、和弦与原创短乐句。
- 每层 `start` / `length` 是整段时长的比例；包络 attack / sustain / decay 是该层时长的比例，三者和为 1。decay 为二次衰减；滤波和相位延迟之后再加包络，避免边界残留。
- 支持以半音为单位的滑音、颤音、占空比与扫动、噪声混合、一阶低通/高通、无反馈变化延迟的相位染色、重复包络/扫频。重复不重置振荡器相位，外层包络仍释放至零。
- seed 为 uint32。Mulberry32 仅在本次渲染中持有局部状态，各层种子派生独立；不使用 Math.random，也不接触引擎 RNG。确定性保证是**相同参数、采样率、JS 运行环境得到逐字节相同 Float32 PCM**；不同浏览器 Math.sin 等实现末位的一致性不作保证。
- 渲染率默认 44,100 Hz，可传入 8,000–96,000 的整数采样率。播放器使用实际 AudioContext.sampleRate；长度为 `round(durationSeconds * sampleRate)`，量化误差不超过半个输出采样点。
- `targetRms` 是线性振幅 RMS 目标；渲染完成后只施加一次线性增益，并受 `peakLimit` 限制，不用硬削波。长尾噪声类别使用较低目标，避免某一变体触及峰值上限而被额外压低。
- 同类变体使用相同响度目标；变体 1/2/3 相对变体 0 分别移调 +1.6 / -1.3 / +2.8 半音，滤波频率同步改变，噪声 seed 也不同。这属于离线音色设计，不是播放时的随机变速。
- 全库 44.1 kHz PCM 共 1,340,918 帧，约 5.12 MiB；总长度 30.406304 秒。试听每段之间留 180 ms，完整一轮约 43 秒。

## 播放接口与并发策略

原版证据为 `SoundEngine.java new SoundPool(8, 3, 100)`；优先级 1、不循环、rate=1、左右等音量。原版具体抢占顺序没有证据，下面明确属于移植实现选择：

1. 全部音效共用最多八路。第九个有效请求立即停止**最早开始、仍在播放**的声音，然后启动新请求；同帧相同音效不去重。`onended` 尚未派发但 AudioContext 时间已超过 endsAt 的声音会先清理，不误抢占较新的声音。
2. 所有 source 的 loop=false、playbackRate=1。声源为 mono，经 master gain 进入 destination；没有额外随机音高或声像。
3. master 使用 `volume / 8` 预留最坏情况混音余量。库内单声峰值不超过 0.8，八路完全同相叠加也不超过 0.8。代价是单个音效相对缓存波形低约 18.06 dB；为保证混音不削波作此保守选择，手机端主观响度仍待试听。音量设置以 5 ms 时间常数平滑变化。
4. `setMuted(true)` 会停止现有声音，后续请求丢弃；不会在取消静音时补播。volume=0 也丢弃新请求。参数无效始终抛错，不被静音掩盖。
5. 抢占为立即 stop，没有跨越八路上限的交叉淡出；极端连续冲击可能有截断感。这不是对原生 SoundPool 行为的声称。
6. `play(id, variant?)` 返回 `Playback | null`。成功时可 `await playback.finished`，也可 `playback.stop()`；自然结束、抢占、停止、dispose 都会完成 finished。尚未缓存、音频暂停/锁定或静音时返回 null，不排队补放。未知 ID、越界/非整数变体抛 RangeError。
7. 变体编号从 **0** 开始，对应 `GetSoundMapping @0x67ea4 RandI(0,n-1,RAND_COSMETIC=0)`。多变体省略 variant 会抛错；单变体可省略并固定用 0。播放器绝不自行抽样或轮换。
8. `preload()` 可在启动阶段调用，按音效类别让出事件循环，重复调用复用同一 Promise 和缓存。每个实例独立持有缓存。`unlock()` 要直接在真实 pointer/click/key 手势处理函数内调用，先 resume 再 await；被浏览器拒绝时 Promise 拒绝，可下一次手势重试。`bindUnlock(target,onError)` 会监听 pointerdown/touchend/keydown 并返回卸载函数；平台从后台回来后也能重试。
9. `dispose()` 停止音源、清空缓存、解除手势绑定、断开 master；只关闭内部创建的 AudioContext，不关闭调用方注入的 context。

## U02 / U04 接入

基础接入可在 UI 的生命周期中执行，不需要修改规则引擎：

```ts
import { SfxPlayer, soundPresets } from '../src/audio/player';

const audio = new SfxPlayer({ volume: 1 });
void audio.preload().catch(showAudioError); // 启动时缓存，尚未播放
const detachUnlock = audio.bindUnlock(window, showAudioError);

// 首次按钮交互需要保留该次声音时，在真实手势内直接调用 unlock：
startButton.addEventListener('click', () => {
  void audio.unlock().then(running => {
    if (running) audio.play(0, 0); // click；只在确有按钮触发时调用
  }).catch(showAudioError);
});

// 请求必须已由表现时间线过滤，并有外部明确选好的零基变体。
function playCue(cue: { soundId: number; variant: number }) {
  audio.play(cue.soundId, cue.variant);
}

// 设置菜单：audio.setVolume(0.7); audio.setMuted(true);
// 卸载：detachUnlock(); await audio.dispose();
```

`showAudioError` 和 startButton 是宿主 UI 的错误提示与实际按钮。SfxPlayer 的 play/setVolume/setMuted 结构兼容 U02 的 `ui/audio.ts AudioPort`；preload/unlock/dispose 需由宿主单独管理。本卡没有修改或接线 `ui/`。

**外部变体选择策略：** 当前引擎尚无 SoundQueued 事件和统一音效 COSMETIC 消费（12 号规格的未决问题）。U02/U04 可以持有一个独立的表现随机源，再把选出的编号传给 play；它不得使用 `RunState.rng`，也不得把声音状态写进规则存档。`soundPresets.find(s => s.id === id)!.variants.length` 可取得上界。若要完整原生 COSMETIC 对齐，后续规则卡必须补排队/抽样时序及测试；即使单变体，也应按原生 GetSoundMapping 的调用语义处理一次 RandI，而不是把播放器默认 0 当作已消费 RNG 的证据。试听页的顺序枚举仅供验收，不是游戏选择规则。

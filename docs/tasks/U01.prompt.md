# U01 表现层规格提取：屏幕布局、流转、动画、音效、字符串、美术需求

**阶段**：P3 第一张卡，后续所有 P3 卡都依赖本卡。
**执行者**：Codex（gpt-6-astra）
**前置阅读**：
- `AGENTS.md`；
- `docs/P3-PLAN.md`，其中的用户决定是硬约束；
- `docs/spec/00-overview.md`；
- 现有调试界面 `ui/main.ts`，用来了解引擎事件怎么被消费。

## 目标

和 P1 一样，**只做规格，不写界面代码**。要还原原版界面「长什么样、怎么动、什么时候发声」，写成后续卡可以直接据此实现的规格，并让每条结论都有证据。

## 输入

- `reverse/native/ghidra/`：按类找以下函数。
  - **主要类**：`App`（含 `resize`）、`Interface`、`ClassScreen`、`FoldoutMenu`、`HelpMenu`、`ScoreScreen`、`Menu`、`Font`、`Label`、`SimpleLabel`、`Token`、`Particles`、`Quad`。
  - **`Game` 的表现相关方法**：`Render`、`UpdateDimming`、`InitialiseFlares` / `AddFlare`、`ProcessResourceShadows`、`ProcessShieldShatter` / `Chunk`、`UpdateCrossVisibility`、`UpdateHelpState`、`QueueSound`、`QueueAchievement`；
  - 所有构造函数和 `Initialise*` 中的常量。
- `reverse/jadx/sources/com/fireflame/dungeonraid/`：
  - `DungeonRaidRenderer`：视口和投影；
  - `DungeonRaidSurfaceView`：触摸；
  - `SoundEngine`：音效 id 到文件的映射、音量和并发；
  - `TextureManager`、`FontFactory`；
  - `DungeonRaidActivity`：生命周期、暂停、返回键。
- `reverse/apktool/res/`：
  - `raw/*.fnt`：位图字体度量，用来推断字号和行高；
  - `raw/*.ogg`：只读取时长和文件名，用来对齐音效触发表；
  - `drawable-nodpi-v4/*.png`：**只允许**用来辨认某个 UV 区域画的是什么元素，从而给元素命名和描述。**不得**复制、裁切进仓库，也不得作为后续生成美术的输入。

## 产出

### 1. `docs/spec/10-ui-screens.md` 和 `data/ui-layout.json`

- **坐标系**：逻辑分辨率（预期是 320×480 竖屏，以证据为准）、原点、Y 轴方向、`resize` 时的缩放和留边规则。
- **屏幕清单与状态机**：主菜单、新游戏确认、职业配置的各个标签页、局内、折叠菜单、帮助 / 教程、高分榜分页、暂停 / 返回、局终（死亡、Sprint 胜利、Pretzel 评级）……每个转换都写明触发条件，以及转换时是否有淡入淡出和多长时间。
- **元素表**：每个屏幕列出元素，并在 JSON 里给出结构化数据。每个元素包括：
  - id；
  - 类型：精灵、文字、按钮、进度条、可滚动区域等；
  - 逻辑矩形 x / y / w / h；
  - 锚点；
  - 图集与 UV 矩形，用原版 1024 坐标；
  - 文字的字符串 id 和字体；
  - 颜色和透明度；
  - 层级；
  - 触摸区域及其对应的动作；
  - 可见条件，例如「有技能时」「Sprint 模式」。
- **棋盘区域**：在逻辑坐标中的位置、格子尺寸、连线的绘制方式（线宽、颜色、端点）、选中和调暗效果。
- **HUD**：资源条的位置和填充方式；生命和护甲的显示方式（药水瓶液面、护甲值）；技能按钮的充能显示；毒和燃烧等状态图标；提示框的出现规则。

### 2. `docs/spec/11-animation.md`

列出每一种动态效果，每项包括：触发时机（对应移植引擎的哪个 `GameEvent`）、时长、缓动曲线或积分公式、起点和终点、缩放 / 透明度 / 颜色随时间的变化、使用的 RNG 路数（例如 COSMETIC），以及与其他动画的先后关系。

需要覆盖：
- 格子下落与补充；
- token 飞向资源条（包括 `Token::Process` 的速度积分）；
- 资源影子；
- 伤害和数值飘字；
- 闪光（flare）；
- 粒子（碎裂、火花、爆炸）；
- 护盾碎裂；
- 心跳（低血时）；
- 调暗；
- 菜单展开和收起；
- 帮助提示的淡入淡出；
- 高分榜的翻页。

注意：引擎已经消费了部分 COSMETIC 随机数（见 T04 报告），在规格中标明哪些随机数由引擎提供、哪些可以由 UI 自由决定。

### 3. `docs/spec/12-audio.md` 和 `data/sounds.json`

- `QueueSound` 的全部调用点：音效 id、文件名、触发场景、对应的移植引擎事件。
- 变体规则，例如 `coin1–3` 是随机选还是顺序轮换。
- 音量、音高和并发上限（以 `SoundEngine` 为准）。
- 每个 ogg 的时长，以及听感类型的文字描述，比如「短促金属碰撞」。这份描述留给 S01 按描述原创合成，**不提供、也不分析原音频的波形**。

### 4. `data/ui-strings.json`

收录全部界面上会出现的英文字符串，每条记录包括：id、原文、来源（字符串偏移或函数）、使用位置、长度上限（按版面估算）。范围包括：
- 菜单和按钮；
- 烘焙在图里的标题字：用文字写出它的内容，比如「LEVEL UP!」「Item Shop!」；
- 帮助 / 教程全文；
- 提示框；
- 技能、装备、敌人、职业、种族、优缺点、成就的名称和描述（`data/enums.json` 中已有的可以引用，不必重复）；
- 结算和评级用语；
- 确认对话框。

### 5. `docs/spec/13-art-requests.md`

供 A02 和 A03 使用的美术需求清单：
- 每个需要重绘的界面元素：id、逻辑尺寸、用途、内容描述（只用文字描述「画什么」，不附原图）、状态变体（例如按下、禁用）；
- 9-slice（九宫格拉伸）是否适用。
- 职业图标 10 个、种族头像 10 个、属性 / 优缺点 / 技能图标、HUD 部件、按钮、面板、对话框，逐项列出。
- 装备图标：400 个槽位按装备类别分组的数量和类别，以及名称池与图标的对应关系（见 `data/items.json` 的 `nameMappings`），供 A03 决定基础图的分组。

## 证据与自检

- 每条坐标、尺寸、时长都要标注函数和地址，以及原始常量（浮点要换算成十进制）。查不到的写进「未决问题」，**不要按截图印象或常识补全**。
- 写 `tools/check-ui-spec.mjs`，检查以下几项：
  - `ui-layout.json` 中每个元素的必填字段齐全；
  - 引用的字符串 id 都存在；
  - 引用的音效名都在 `sounds.json` 中；
  - UV 矩形落在 1024 图集范围内。
- 自行抽查 5 条结论，回到伪 C 复核。

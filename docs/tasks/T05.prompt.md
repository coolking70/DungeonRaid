## 环境

与前几张卡相同：依赖已装好，**不要运行 `npm install`，也不要新增依赖**。命令是 `npm run check`。

另外，仓库里现在有一个调试界面 `ui/main.ts`，由 Claude 维护，用 Vite 驱动 `step`。**不要修改 `ui/`**。如果 core 的接口变化影响到它，在报告里写明需要怎么调整，由 Claude 去改。

## 目标

去掉 T04 的 `special-pending` 占位，让 32 种特殊敌人按原版规则完整生成、战斗和发动能力。做完后，整局模拟中出现的特殊敌人都是真实的特殊敌人。

## 要做的事

1. **特殊数值**：通过 `completeSpecialStats` 钩子，或者直接改造生成路径：
   - 实现特殊敌人的 A / D / H / C 倍率、Noisy、尾部修正；
   - Corrosive 生成时清甲；
   - Fleeing 生成时的 JumpDown；
   - 特殊敌人生成相关的成就入队（只入队，成就系统由 T07 实现）。
   - 完成后 `statsStatus` 为 `'special'`。
2. **32 种能力**：按 02 号规格的「特殊敌人能力」表和对应的 Game 函数，逐个实现主动能力（`activateAbility`）和被动能力，包括：
   - 移动类：Teleport、Jump、Flee、Swap、Throw；
   - 转换类：Acid、Convert、Alchemy；
   - 状态类：Freeze、Ignite、Poison；
   - 资源类：StealGold、DestroyUpgrade；
   - 吸引类：AttractSkulls、AttractShieldsSwords；
   - 其他：Healer、Vampire、Lich / 命匣、Meat Shield、Armoured 方向等。

   T04 已经做了一部分最小路径，需要把它们补全，并保证与规格一致。
3. **特殊奖励**：在 `specialRewards` 中实现：
   - `GetRewards` 的奖励组成，比如 Healer 和 Armoured 掉落药水、金币、XP 或盾的比例；
   - Golden 被击杀时的奖励；
   - 奖杯（Trophy）格的生成与间隔，注意它会用到 COSMETIC 那一路 RNG。

   `ClaimTrophy`（领取奖杯后的职业奖励流程）属于 T06，本卡只负责把奖杯格生成到棋盘上。
4. **占位退役**：
   - 生成路径上不应再出现 `special-pending`；
   - 把 `specialPendingCombat` 的默认值改为 `'reject'`，作为防线；
   - 更新 T04 中依赖占位规则的测试和说明。
5. **处理顺序**：能力发动按 EndOfTurn 中的槽位顺序进行（x 外层、y 内层，见 T04 报告），由 `abilityUsed` 负责去重。多个移动类敌人在同一回合的组合（T01 的 C3 / V02）仍然没有原版证据：
   - 保持原生遍历顺序；
   - 已知单体规则正确即可；
   - 不要发明一套全局冲突解决规则。

## 测试

- **E 组用例**：E01–E33 全部写成 Vitest 测试，测试名以编号开头。依赖 T06 内容（技能、装备菜单）的用例，只实现直接需要的最小状态并给出证据；做不到的用 `test.todo` 并在报告里说明原因。**不允许**为了让测试通过而偏离规格。
- **每种敌人的单体测试**：除 E 组外，32 种特殊敌人每种至少再有 1 条测试，覆盖生成数值（倍率与 RNG 调用）或能力边界，例如「没有目标时不消耗 RNG」或「倒计时为 0 时的行为」。
- **整局模拟**：更新 `test/playthrough.test.ts`。
  - 特殊敌人现在是真实的，统计死因分布，例如毒、火、反伤、投掷等；
  - 继续要求同一种子可以逐位复现，并检查每一步的不变量；
  - 如果有些特殊能力在整局里会触发「必须有 T06 才能处理」的路径（例如 DestroyUpgrade 需要装备数值、Mage 影响技能充能），要说明本卡是怎么处理的。

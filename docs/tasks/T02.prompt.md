# T02 规格提取（第二批）：成长、装备、技能、职业 / 种族、计分、存档

**阶段**：P1
**执行者**：Codex（gpt-6-astra）
**前置**：先读 `AGENTS.md`、`docs/PLAN.md`、`docs/tasks/T01.report.md`（特别是其中「对 T02 的建议」和未决问题），以及 `docs/spec/00–02`。

## 目标

补齐 P1 剩下的规格，使 P2 规则引擎能完全照规格编码。本卡**只做规格和数据表，不写游戏代码**。证据要求与 T01 相同：每条结论附函数名、地址、常量或字符串偏移；无法确认的写进「未决问题」，严禁凭印象补全。

## 要产出的内容

### 1. `docs/spec/03-progression.md`：成长与奖励菜单

- 经验、金币、盾三条进度条满时分别打开什么菜单，以及菜单里候选项的生成规则：数量、来源池、权重、RNG 路数、遍历顺序。
- 升级（LevelUp）时属性的增长方式。
- 技能：
  - 获得、升级、冷却、充能；
  - `Skill::Activate` 分发表到每个技能函数，**每个技能**写明效果、数值、随等级的变化；
  - 解决 T01 的未决问题 O1（原生技能 40 / 41 Shock、Awe 实际是否会被使用）、B3（标志 14dab）、C1（Rune）。
- 所有临时状态标志：列出写入位置、消费位置、在回合中如何轮换。

### 2. `docs/spec/04-items.md` 与 `data/items.json`：装备与商店

- 装备槽位（ItemType）。
- 初始装备。
- 商店购买与强化候选的生成：词缀 / 属性的种类、权重、取值范围，以及命名表。
- 每项属性如何作用到战斗公式。要和 02 中的基础伤害 B、每把剑的加成 W、修甲 / 治疗、奖励比例对上。

### 3. `docs/spec/05-classes.md` 与 `data/classes.json`：职业、种族、宿敌、难度、模式

- 每个职业：起始技能、技能池、优点（Perk）和缺点（Flaw）、解锁条件、职业等级的成长。
- 种族加成（RacialBonusType）及附加描述。
- 宿敌机制。
- 难度与模式的差异。T01 已整理了敌人数值，这里只补充其他差异。
- 描述文本与代码不一致的地方单独列表，以代码为准。

### 4. `docs/spec/06-score-and-save.md`：计分、成就、存档

- `GetScore` 按 Classic / Sprint / Pretzel 三种模式分开写；ScoreType、ScorePage / ScoreScreen 的统计口径。
- 成就：Achievement 共 78 项。列出每项的触发条件和来源函数；只能定位到函数、读不出条件的，标记出来。
- 存档：
  - `SerialiseState` / `DeserialiseState1/2`、CharacterClass、Item、Skill、ScoreScreen 的字节布局：版本号、字段宽度、是否有符号、棋盘的半字节打包方式；
  - 新格式与旧格式的差异；
  - RNG 种子的保存范围（T01 的 B4）。

  这份布局用于说明设计，新实现**不要求**兼容原版存档。

### 5. `docs/spec/07-test-cases.md`：P2 行为用例清单

- 把 T01 报告第 5 条建议，以及本卡发现的规则，整理成可以直接写成 Vitest 用例的行为清单：每条写明前置状态、操作、期望结果和证据。
- 至少 40 条，覆盖连线、伤害、护甲、资源条、每种特殊敌人、技能、升级、计分、Sprint 结束条件。

# U19 — 缺少 structuredClone 时无法启动

## 问题与复现证据

玩家报告打开页面即出现 `Unable to start Dungeon Raid: ReferenceError: structuredClone is not defined`。在 Chromium 隔离上下文用 `addInitScript` 删除 `window.structuredClone`，加载修改前的开发版本，得到完全相同的错误。

调用链为 `ui/main.ts → mountApp (ui/app.ts) → new GameSession (ui/session.ts) → new PresentationTimeline (ui/timeline.ts)`。Timeline 构造函数立即复制初始 RunState，此前直接调用全局 structuredClone，没有能力检测。规则引擎 step、职业配置、成就/结算、连线事件、奖励和诊断入口也有同样依赖。玩家具体浏览器/系统版本未提供，因此只能确认 API 缺失触发路径，不推断其设备版本或缺失原因。这不是存档格式错误，也不需要清除存档。

本任务是Web兼容性修复，没有新增原版规则结论；不修改 reverse/、原APK或美术。

## 修改

- `src/core/clone.ts` 提供 cloneData，优先使用原生 structuredClone；缺失时递归复制项目使用的基本值、数组和普通记录。
- 回退保留 undefined、自身属性、稀疏数组、非有限数值、负零、重复引用与循环；与输入隔离。使用属性定义避免把 `__proto__` 当作原型修改。遇到函数、Symbol值或非普通对象显式报错，不静默变成空对象。它是项目数据复制助手，不是完整浏览器结构化克隆polyfill。
- `src/core/` 和 `ui/` 所有运行时调用均改用该助手，包括公开与debug入口。未覆盖全局API，也没有把JSON序列化作为复制方法。
- 同类检查发现 Array.at 与 Object.hasOwn：连线、箭头、界面栈、音效和读档校验改用数组索引及 hasOwnProperty.call，避免同一类环境继续发生错误。Node工具和既有测试中的原生API不属于浏览器运行时。
- 不修改玩法、RNG、存档键/格式或已有数据。

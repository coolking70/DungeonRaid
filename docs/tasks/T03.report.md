## 实现边界

本卡完成地基，不实现连线结算、普通敌人攻击、回合末推进、奖励菜单业务、技能或特殊敌人能力。

- 特殊敌人抽取保留 `R(1,32,TILE)`、非 Adventurer 的宿敌覆盖抽样、共同 A/D/H/C 抽样和计时重置，但标记 `statsStatus='special-pending'`。现有 A/D/H 只是共同基础值，**不可当作最终特殊敌人战斗数值**。同时发 `SpecialEnemyPending`，并在状态 diagnostics 中留痕。
- 特殊倍率、Noisy、特殊敌人尾部修正、Corrosive 清甲、Fleeing 的生成 JumpDown、特殊生成成就留给 T05；提供 `completeSpecialStats` 和 `specialSpawn` 两个不同阶段的扩展点。
- 如果直接构造已有 Fleeing 的下落 fixture 而未提供 `fleeingFell`，在改盘前明确报 T05 错误；有钩子时，全部列处理完后按目标物理槽索引升序调用。没有静默遗漏 Stab，也没有提前实现其死亡/Last Stand 结算。
- `initialisePlayer` 只处理初装数值，通用换装/升级后的 UpdateStats 与技能冷却变化由 T06 实现。当前全部初装非零值来自 items.json，Slim/Pretzel 例外也读表。
- NewGame 使用选定职业的默认配置；长期已解锁状态、自定义种族/特性和替换技能的注入由成长/外围卡接入。ProfileState 工厂已经按表保存这些字段。
- 新局边界创建全新的局内暂态。`trophies.remaining=0` 取 Game 构造初值；不复刻旧 Game 对象跨局遗留内存（InitNewGame 本身没有重置14da0），详见下文问题记录。
- 被清空的非敌格采用规范化零值载荷，不保留其旧敌人的无效 HP/毒等内存残留。固定槽身份、活跃实体载荷、matched/new 标记和随机消耗保留；不承诺原生对象每字节相同。

## 给 T04 的接口说明

```ts
import { step } from '../../src/core/engine';
import { createRunState } from '../../src/core/state';
import { Difficulty, GameMode, enumValue } from '../../src/core/data';

const result = step(createRunState(), {
  type: 'NewGame', seed: 12345,
  classId: enumValue('ClassType', 'CLASS_ADVENTURER'),
  difficulty: Difficulty.DIFF_NORMAL,
  mode: GameMode.MODE_CLASSIC,
});
```

1. `step(input, action, { rng?: hook })` 是转换边界，输入不会被修改；目前只有NewGame有效。新增动作时沿用一次深复制后内部可变写法，不能在每个规则函数中反复复制。Action已有十种后续动作形状，未实现动作目前抛错。
2. `createRunState(overrides)` 构造未开局的结构基线；`phase='idle'`、格子NONE不是有效初盘，需NewGame。`createProfileState()` 单独创建长期状态；不要把profile合入每次回合复制的大对象。
3. 棋盘一维行优先，`slotIndex(x,y)=6*y+x`，`tileAt`校验坐标。链、忽略格、敌人目标、moving列表都保存槽索引。`moveMatchedTiles`交换槽内载荷，槽对象身份稳定；调用者不要把实体身份等同于槽对象引用。
4. 规则内部用 `new NativeRng(state.rng, hook)` 或注入 `RandomSource`；所有抽样显式指定RandType。对象本身不拥有隐藏种子。flush算6次记录，set/get不抽数；Rand/RandI各只记录一次，不额外记录内部RandUnitF。序号保存在state中，可跨规则调用继续。
5. `randomiseTile(state,tile,rng,events?,hooks?)`、`setTileType`、`generateStats`、`moveMatchedTiles`均可在fixture直接调用，**会修改传入状态**。补盘不会自行结束回合、消费pending、清所有newThisTurn、减少晋升计时或推进phase；这些归T04阶段协调。
6. `moveMatchedTiles`将洞位matched清零、新格newThisTurn置真；既有格完整保留标志/毒/敌人载荷。`moving`是追加队列，消费/清理归T04；不要在每次补盘开头清空先前移动。
7. 普通攻击必须排除newThisTurn。不同遍历显式选用 `rowMajor()` 与 `refillOrder()`；随机set目标按物理槽升序，不能套补盘序。
8. 资源 `banked` 是已跨过的整百累计；总量=banked+remainder。`carry`独立float32累积，不能把bonus改成总资源乘法。升级队列和pending有稳定ID占位，后续要保持点击/消费顺序。
9. 基础攻击和装备附加分别为base.damage/equipmentStats.damage；W是equipmentStats.weaponDamage；不要再用初始四属性1重算一次基础奖励。通用UpdateStats尚无实现。
10. 出现 `special-pending` 时，T04不得据其共同基础值执行特殊战斗；可用只有普通敌人的fixtures推进C组测试。T05完成倍率后改`statsStatus='special'`，并接入生成/下落能力钩子。
11. core不使用DOM、Canvas、计时器、系统时间、Math.random。seed由调用者提供；渲染若消费COSMETIC也必须走同一个显式状态，才能讨论跨UI回放。

## 规格问题与未决事项

### 新发现：RandI的小区间也可能向上越界

01将公式的警告限定为“极大数值”，但按其公式在小整数也能构造反例：

```text
SetRandSeed(3016468969, TILE)
nextSeed = 0xffffffff
u = 1 - 2^-22
RandI(5,5,TILE)
  = floor(float32(5 + float32(1*u)))
  = floor(6)
  = 6
```

Thumb @0x57c20 转换下界，@0x57c24 `vmla.f32`，@0x57c2c 调floorf，@0x57c34转有符号整数，至return没有结果钳制。整数跨度也先在ARM寄存器中溢出（@0x57c00/02、@0x57c40/42），代码用isub/iadd保留。

处理：遵守已有float32公式，增加独立反例测试，不在RandI偷偷加端点钳制，不改现有规格。常用0…4、0…7和1…100抽样测试通过；这里不宣称任何a/b都绝对落在数学闭区间。后续大下界同样应注意此效应；尚未用原版运行验证这个极端seed。

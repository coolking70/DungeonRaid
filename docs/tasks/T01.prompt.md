# T01 规格提取（第一批）：数据模型、棋盘与回合结算

**阶段**：P1
**执行者**：Codex（gpt-6-astra）
**前置**：先读 `AGENTS.md` 和 `docs/PLAN.md`。

## 目标

从 `reverse/` 中的反编译材料还原原版游戏的**核心规则**，写成可以直接据此编码的规格文档和数据表。本卡**只做规格，不写游戏代码**。

## 输入

- `reverse/native/ghidra/`：Ghidra 伪 C，一个函数一个文件，另有 `functions.tsv` 索引（地址、大小、去修饰后的名字）。
- `reverse/native/strings.txt`：带偏移的字符串表。
- `reverse/native/disasm-thumb.txt`：Ghidra 输出存疑时，以反汇编为准。
- `reverse/jadx/sources/com/fireflame/dungeonraid/wrappers/`：SWIG 接口。其中的枚举顺序就是原生侧的整数值。
- `reverse/apktool/res/`：贴图、音效、字体（用来理解有哪些表现元素）。

## 要产出的内容

### 1. `docs/spec/00-overview.md`

- 原生侧的类清单：`Game`、`Tile`、`Item`、`Upgrade`、`Skill`、`CharacterClass`、`GameState`、`Menu`、`Interface`、`ScoreScreen` 等。
- 每个类写明职责、主要字段（从构造函数和 Serialise 函数推断偏移与含义）以及关键方法。
- 一张主循环时序图：`App` → `Game::Process` / `Game::Render`，触摸事件如何进入。

### 2. `data/enums.json`

- 包含 wrappers 里的全部枚举：TileType、EnemyType、ItemType、SkillType、PerkType、RaceType、ClassType、Difficulty、GameMode、StatType、DamageType、FlawType、RacialBonusType、SpecialTileType、ScoreType、RandType、TouchState 等。
- 每项给出名字和整数值。
- 在原生侧的字符串表里找到对应的显示名和描述，同样写进去。

### 3. `docs/spec/01-board.md`：棋盘

- 尺寸、坐标系、初始生成规则（各种 tile 的权重或概率，以及难度和模式对它的影响）。
- 消除后下落和补充的规则，包括新 tile 的生成概率，以及特殊 tile、敌人生成的条件与频率。
- 随机数生成器：算法、种子来源、各 `RandType` 的用途。

### 4. `docs/spec/02-chain-and-turn.md`：连线与回合结算

- 连线规则：同类 tile 的判定（例如剑与骷髅是否可以互连）、邻接方向、最短长度、能否回退。
- 结算顺序，按 tile 类型分别写明：
  - 剑 / 骷髅：伤害公式，包括武器基础值、每把剑的加成、暴击和其他修正；
  - 盾：护甲修复与上限；
  - 药水：回血与溢出；
  - 金币：计入金币条，满了之后触发什么。
- 敌人回合：哪些敌人会攻击，伤害怎么被护甲吸收，护甲如何破损，特殊敌人的能力。
- 回合计数、经验 / 金币 / 盾三条进度条满时触发的事件（这些事件的具体内容留给 T02，这里只写触发条件）。
- 胜负条件。

## 证据要求

- 每条结论后面标注证据，例如：`[证据: Game::ResolveChain @0x1234 —— 常量 0x14]`，或字符串偏移、wrapper 文件行号。
- 不能确认的内容放到各文档末尾的「未决问题」小节，写清楚尝试过什么。**严禁凭对原版游戏的印象补全**。
- 数值以反编译常量为准。浮点常量要换算成十进制。

## 自检

- `data/enums.json` 里每个枚举的项数与 wrappers 里的 Java 文件逐一核对（写一个小脚本放在 `tools/check-enums.mjs` 并运行）。
- 抽查自己写的 5 条规格，回到伪 C 复核一遍，把复核结果写进报告。

### 特殊敌人的占位规则

T04任务卡明确允许整局模拟把 `special-pending` 作为普通敌人，故默认新增 `specialPendingCombat='ordinary-placeholder'`，并在新局 diagnostics/CompatibilityNotice 中告知：

- 保留T03的生成抽样、原enemyType、共同A/D/H、晋升计时与 `SpecialEnemyPending` 事件；不伪造特殊倍率。
- `effectiveEnemy` 对尚未完成数值的格返回普通敌人身份：选格/战斗/被动查询按普通路径，死亡发一个普通XP，回合末不执行特殊能力，不产生特殊奖励/奖杯；Fleeing占位的下落不Stab。
- T03已实现的生成分支保持原样，例如已知Invisible生成修正。本策略不重写生成器。

## 给 UI 的接口

只从 `step(state, action, hooks?)` 推进；不要从UI调用测试用的可变内部函数。

- `SelectTile/ExtendChain {at:{x,y}}`：首选/扩展，触到链内任意旧格自动回退；`Backtrack {at}`显式回退。保留T03的 `{slot}`别名；新输入使用坐标。
- `CancelChain`清选择；`CommitChain`提交，兼容别名`SubmitChain`。不足3个有效格只取消，仍在input。
- `state.preview` / `ChainPreview`事件：effectiveLength、valid、damage、leech、spikes、fire、resources、enemies。enemies包含槽号、传入伤害、穿甲后的HP伤害、lethal和transforms（巫妖转命匣）。预览不抽随机数；回退后重算。
- `resources`是五类保证产生的普通token数（不是资源点数），含普通致死XP和Steal金币；不预测随机bonus、特殊奖励、法力/酸/爆炸的间接收益，也不承诺未来入账先后造成的护甲/治疗转换。伤害预览可用于“会打死谁”；特殊能力钩子造成的额外变化归T05。
- `hitTile(point)`是可选纯函数，输入以格为单位，中心为(x+.5,y+.5)，半径.4。像素到该坐标系由UI完成，core没有触摸/DOM依赖。
- `EffectQueued`包含稳定ID及资源类型/variant/绑定技能槽/直伤或治疗数值。`ConsumeEffect {id}`在falling或arrivals时消费指定效果一次。资源与吸血/火/尖刺可按UI实际到达顺序发送，core不会自动全部先治疗或先伤害。
- `falling`时`AdvancePhase`确认本批移动完成并清moving；不清新格标志。`arrivals`必须pending/moving/menu全空才能`AdvancePhase`；然后进入enemy-attack或end-turn。继续`AdvancePhase`执行当前规则阶段。
- `MenuRequested`后phase=menu，其他输入/效果到达/推进都暂停。`ChooseMenuOption {menuId, option:'skip'|'confirm'}`仅关闭队首；兼容`ConfirmMenu`。本卡候选为空，两种选择均不改变属性装备，T06替换具体选择逻辑。
- `resumePhase`记录本批效果清空后去哪；`menuResumePhase`记录菜单关闭后恢复哪一个等待阶段。回合末产生的毒杀/火杀token清空后直接回input，**不再发动一次敌攻**。
- `PlayerHealth`、`EnemyDamaged`、`EnemyAttack`、`TileMatched`、T03的生成/移动事件可供动画使用。`TurnEnded`表示EndOfTurn主体完成，不等于其奖励动画已到达。
- 终局phase=`ended`、`outcome`为最终胜负/死因/回合；发一次`GameOver`并附资源、HP、击杀统计，完整最终状态仍由step返回。终局未消费视觉效果队列被明确丢弃，不允许随后治疗复活。计分/成就/长期职业记录由T07接入。

## 规格问题与未决事项

1. **C2与完整原版轨迹仍有边界。** 已补入 `Token::InitialiseFromTile @0x653d0` 的4次基础Rand及XP第5次；无目标法力token在抽0路之前退出。粒子由 `Particles::InitialiseFromTile @0x5aaf8` / `InitialiseAtPosition @0x5a7d4` 可证明固定33/81次，几何参数不会改变抽样个数；这里逐次调用原始unit以保留种子和路数顺序，未虚构依赖UI尺寸的Rand区间，因此其trace operation显示RandUnitF，而非原版Rand。flare、普通标签和飞行参数的已知区间直接调用Rand；SimpleLabel伪C缺失的第三参数已由Thumb @0x4fbfc–0x4fc1e证实为0。它们在对应规则位置消费，UI不要再次推进这些同名抽样。仍没有Token::Process速度积分或原版逐帧golden trace；T05特殊能力和T06菜单尚未接入时，不能将占位局的全局六路轨迹当作原版全局轨迹。首次检查时发现的“收集后漏掉0路消耗”已修复，不把这项缺口遗留给表现层。
2. **ProcessAttack的装备效果有阶段门槛。** 伪C @0x311b8 中weaken/spikes在状态5（当前甲>0的格挡路径）内；零护甲直接走6，不执行这两段。即便部分攻击穿透，仍以旧护甲一次挡完。代码及新增测试保留该结构；02的文字可以读成无条件执行，本卡没有改规格。

## UI 影响

未修改 `ui/`；`npm run check` 的 TypeScript 检查包含 `ui/`，当前调用仍兼容，继续只用 `step(state, action)` 即可。不需要安装或传入特殊能力钩子。

建议 Claude 调试界面接入：

- `SpecialEnemyGenerated {slot,enemyType}` 替换旧 `SpecialEnemyPending` 日志；后者联合成员仅保留源码兼容，正常生成不会发出。
- `EnemyAbility {slot,enemyType}` 表示本槽通过 abilityUsed 门槛（无主动case的敌人也会置位）；`TrophyGenerated {slot}` 提示奖杯出现。交换沿用 `TileMoved`，棋盘槽对象不会成为实体永久ID。
- 显示 `countdown`（Golden/Kamikaze/Unstable/Devourer），`enemyType=LICH && countdown!=0` 显示命匣，`phylacteryDelayed` 可供调试复活延期。
- UI 已有冻结颜色和火图标，可增加 `fireDamage`、`fireSafe`、敌毒三槽，以及法力/酸药/破损的清晰标记。特殊数值现在是真实值，旧 `special-pending` 的 `?` 不再正常出现。
- 渲染 `type=TILE_SPECIAL && specialType=SPECIAL_TILE_TROPHY`。T06接管前奖杯可以留盘，不应提交 `ClaimTrophy` 并期望普通回合或自动职业奖励。
- 新伤害来源 `assassin`、`thief`、`kamikaze`，已有 `fleeing`/`thrown-skull` 也会实际发生；沿用 `PlayerHealth`/`GameOver` 即可展示。
- `classLevels` 默认取 classes.json 的初始等级；已有长期 Profile 的前端应在新局前填入 `profile.classes.map(c=>c.level)`。引擎 NewGame 保留快照。后续职业升级/解锁时由 T06/T07同步，不能把局内 XP 等级当职业等级。

`completeSpecialStats`/`specialSpawn` 目前是原生默认处理之后的可选观察/覆盖钩子，旧代码不应再次乘特殊倍率；`specialSpawn` 若遇 JumpDown，所传对象是原固定槽，载荷可能已交换。`activateAbility`/`specialRewards`/`fleeingFell` 保留显式替换钩子供受控 fixture 用，默认真实规则不依赖它们。低层 `moveMatchedTiles` 仍要求调用者提供 Fleeing 回调；业务层统一通过 `refill` 提供包含伤害、RNG和终局事件的默认实现。

1. `updateEquipmentStats` 可供换装/强化复用；不调用 `initialisePlayer` 重置基础属性或生命。保持护甲缺口、HP上限降低时只钳当前HP、Quicken开关改变时调整既有技能CD与charge。

3. Trophy 实际上已通过原 SetType 路径生成，含两次 COSMETIC抽样与 `matched=false`。T06只接领取、职业菜单/解锁和 `classLevels` 同步，避免再次生成奖杯或消费普通回合。

6. 原 T04 的 Halfling≥15杀装备成长、Rune、技能施放及菜单候选/确认仍由T06实现，原来的明确错误边界没有被伪实现替代。两种菜单/效果续接字段继续保留。

## 规格问题与未决问题（只记录，未改规格）

1. **Acidic / Overseer 的候选与无目标 RNG。** 02表说“未消除”，实际 MakeAcidPotion @0x2ea40 / GetNormalPotionCount @0x24804 和 ConvertSwordToSkull @0x2eb4c 都没有 matched 检查；先无条件抽 `R(0,count−1,OTHER)`，空集合即 `R(0,-1,5)`，然后按列扫描。实现与测试按原函数，不套用其他能力的set筛选与空候选早退。
2. **SetType 不清 abilityUsed。** @0x64ef8 清冰火/变体/倒计时/选择/晋升/命匣延期，但没有写+0x264；T03使用emptyTile重置它，会影响能力阶段内重生成后的再次访问。已改为保留，并更新旧测试。其他非活跃载荷仍沿用T03规范化零值原则。
3. **特殊奖励 token 源格。** MatchTile @0x2ac40 调 AddToken 时用 `board[0]` 加独立位置参数；Token::InitialiseFromTile @0x653d0 从源格实际类型/标志推导variant。因此左上为法力药会影响所有这些token的初始化/隐藏与OTHER目标抽样；左上为酸药会令药水奖励带酸variant。非药水奖励最终仍按其token类型入账。代码保留可证明的调用，不按“奖励当然是普通药”改写；需P6实机确认可见表现。
4. **Trophy 会改变后续击杀成就检查身份。** MatchTile 在 SetSpecialType→SetType 清enemy后再读enemy判断Golden/Chaotic成就；生成Trophy的那次不进入这两个旧身份分支。保留原顺序；通用特殊收集和Changeling分支仍继续。
5. **Thief 宿敌扣血只在金币条路径。** @0x348e8 的棋盘金币偷取不扣玩家HP；@0x34a68 的无金币候选分支才每扣1条金币扣一次GetAttack。只有1个棋盘金币时也不补扣条。原生条偷取可以短暂写负HP；移植沿用既有 `hurt` 的非负规范化并在原回合检查点结算，不把负HP作为可继续输入的状态。
6. **交换和补盘仍按原顺序，无全局冲突解决。** 原 SwapTiles @0x28b14 设置移动载荷；移植使用显式moving/TileMoved描述供界面确认，不模拟速度积分。能力遍历不新增matched/new/frozen过滤；保留abilityUsed、物理槽set顺序和Brute列vector顺序。测试证明已知单体/移动防重行为，**C3/V02多个移动敌人的原版运行轨迹仍未取得**；不宣称组合golden trace已验证。
7. **C2完整表现时序仍开放。** 已保留本卡可证明的token、标签、flare、粒子及奖杯抽样，包括无目标分支；继续沿用T04粒子几何无关的原始unit推进。没有原版Token速度积分/逐帧菜单竞争日志，不能把同种子自回放等同于完整六路原版对拍。奖杯有意使用COSMETIC，UI不应重复推进引擎已经消费的抽样。
8. B1初始过滤子标志、B2零回合特殊间隔、I1卷轴过滤、C4完整种族技能组合以及跨局奖杯间隔仍为原有未决项。本卡没有添加武断默认规则；普通生成的B2处理和特殊零回合拒绝边界保持原状。

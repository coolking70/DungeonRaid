## 目标

做完本卡后，P2 规则引擎完整收口：
- 三种模式都能计分并结算；
- 成就和长期档案（职业等级、统计、高分榜）有完整的纯函数实现；
- 局内状态能存档和读档，读回后继续游戏的结果与不中断时完全一致；
- 有一个大规模的随机机器人，检查长期不变量。

## 要做的事

1. **计分与 Pretzel 模式**
   - 实现 `GetScore`，Classic、Sprint、Pretzel 三种模式分开实现，规则见 06 号规格「计分与排行榜」。
   - 实现 Pretzel 模式的 `ProcessPretzels`：连线交叉统计、平均交叉数、评级。这部分原先只有字段，需要做成可玩的完整模式。
   - 整理局终结算事件，供 UI 显示，内容包括分数、各项分解、评级。
2. **成就**
   - 消费 `achievementQueue`：Easy 难度下的抑制规则、去重、进度累计、职业里程碑成就。
   - 成就 45（ACH_I_SEE）没有触发证据，保持不可解锁并注明。不要猜它的条件。
3. **长期档案 `ProfileState`**，用纯函数实现：
   - `applyRunResult(profile, finalRunState)`：职业的局数、击杀和最佳分，高分榜六个类别，每类最多 10 条，同分时的排序规则按 06 号规格；
   - 应用 `ClassLevelChanged`；
   - `classLevelsFromProfile` 用于新局开始前的同步；
   - 跨局的奖杯间隔：处理 T03 留下的 Game+14da0 问题。原版是否会让奖杯间隔沿用到下一局？请给出有证据的结论，并做成一个选项；默认值的理由写进报告。
4. **新存档格式**
   - core 里只放纯函数：`serializeRun` / `deserializeRun` 和 `serializeProfile` / `deserializeProfile`。真正的 localStorage 读写由 UI 负责。
   - 格式带版本号，能完整往返，包括：菜单候选、选择顺序、卷轴、技能的原生 ID、本回合与下回合的标志、待结算效果中绑定的技能槽号、两个续接字段、**全部六路 RNG**（包括 COSMETIC）、`classLevels`。
   - 读档时校验输入，遇到不合法的数据要明确报错，不能静默修复。
   - 不实现原版 FF03 格式的读写。
另外，S 组里有一部分用例是针对原版存档字节布局的，例如 S11–S16：
   - 把它们改写为「新格式下保留了同样的语义信息，并且能完整往返」的测试，测试名仍以原编号开头；
   - 在报告里说明这种改写与原用例的差别。
   - 不要为了这些用例去实现原版字节格式。
5. **确定性存读档**：任意时刻存档、读档后继续游戏，必须与不中断时逐位一致，比较完整状态和 RNG 调用序列。
   - 用整局模拟验证：在随机选取的若干回合、以及菜单打开时、`falling` / `arrivals` 阶段中间做存读档。

## 测试

- **S 组**：S01–S20 全部写成测试，测试名以编号开头。做不到的用 `test.todo`，在报告中说明原因。**不允许偏离规格**。
- **成就**：至少覆盖 20 个成就的触发，以及 Easy 抑制、去重、进度累计。
- **千局机器人**：
  - 新增 `tools/soak.mjs`，或一个 vitest 文件配合单独的 npm 脚本 `npm run soak`。**不纳入** `npm run check`，因为太慢。
  - 混合使用 1000 个种子 × 三种模式 × 四种难度 × 若干职业。
  - 策略带少量确定性随机性：用独立的 PRNG 选择连线、菜单候选和技能施放时机，不能使用引擎的 RNG。
  - 每一步检查不变量；每局结束后调用 `applyRunResult`，并检查档案的不变量。
  - 输出统计：平均回合数和分数（按模式与难度分组）、死因分布、每种特殊敌人和每个技能的出现或施放次数、成就解锁次数、异常数。
  - 出现任何异常时，记录种子和动作序列，以便复现。
- **`npm run check` 中的子集**：放 30 局左右，作为常规回归。超时用 `SIMULATION_TIMEOUT_MS`。

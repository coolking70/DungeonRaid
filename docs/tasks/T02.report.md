## 对P2的接口建议

以下是移植设计建议，不冒充原版已有TypeScript接口。

1. **纯状态与阶段。** 将局内RunState和长期ProfileState分开。RunState含6×6格、基础/装备派生属性、五装备、四技能、三条余数/累计/carry、玩家毒、晋升计时、当前/后继技能flags、链节点/箭头忽略格、待结算资源/伤害、菜单队列、回合阶段、六路RNG状态。Profile保存十职业配置/等级/统计、成就进度、六类高分。不要只保留一个总HP/总伤害而丢失基础与附加字段。
2. **可暂停的动作/事件。** 动作建议含开始新局、选择/回退/取消/提交链、手动施放技能、选择菜单项与确认、领取奖杯、消费指定待结算事件、推进明确阶段。输入坐标命中与帧计时留UI；规则返回state+events。手动施放与卷轴施放带来源，保留Dragonkin钩子的区别；菜单0的两个选择按点击顺序应用。
3. **多路RNG注入。** RNG接口显式接RandType，区分float32 Rand和含端点RandI；六路各持uint32状态，测试可注入按路抽样队列并断言调用顺序/范围/次数。0 COSMETIC虽然名字像表现层，原版奖杯会使用，不能删除。新存档建议保存全部六路以及必要队列/carry；这属于新格式设计，不承诺与原版FF03等价。渲染也消费0时，忠实原版轨迹需要明确双方调用边界，不能悄悄只保存种子就宣称完成确定性。
4. **数据身份与兼容边界。** WrapperSkillId仅0…39，NativeSkillId可0…41，属性奖励内部起点42，ItemUpgradeId单独0…19。职业原始vector保留首项语义、抽样再转升序set；名称池保留重复权重。I1应作为独立的待定兼容策略，不散布原生地址算术到新规则；S1不影响选择新的版本化存档。
5. **按清单验证。** 先做07的纯阶段fixture、每种敌人单体与装备阈值，再做菜单RNG调用序列、完整回合、存档往返；待B1/B2/C2/C3获得证据后补原版golden trace。时间/动画不可直接进入src/core，未决竞争保留显式事件暂停点，不臆定“所有治疗先结算”。

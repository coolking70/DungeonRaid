## Screen API 与扩展

```ts
interface Screen {
  readonly id: string;
  readonly overlay?: boolean;
  enter(): void;
  exit(): void;
  update(dt: number): void; // 秒
  render(ctx: CanvasRenderingContext2D): void;
  input(event: { type: 'down'|'move'|'up'|'cancel'; x: number; y: number }): void;
}
stack.push(screen, seconds);
stack.pop(seconds);
stack.replace(screen, fadeOutSeconds, fadeInSeconds);
stack.paused = true;
```

入栈调用新屏幕 enter；出栈淡出结束调用 exit；替换先退出旧屏幕再进入新屏幕。过渡期间忽略输入和进一步栈操作（返回 false），栈底不能 pop。overlay 可绘制底层屏幕，但底层不会 update。主菜单进入0.5秒/退出0.3秒、启动0.51秒、游戏菜单0.2秒、奖励菜单0.3秒；未确定的局终完整分阶段动画尚未实现。

U03 可在独立模块实现 `Screen`，在 `app.ts` 的组装点替换 `Main/Settings/Stats/GameOver` 等占位类，通过构造参数传入 `session/assets/i18n/stack`。无需改动规则控制器或视口。`Panel` 目前只是占位按钮绘制辅助，不是原版控件或最终布局系统；各屏幕输入边沿应按10号规格分别实现，不能把其通用 down/up 语义当作全部原版按钮语义。

## 时间线 API、时序和 RNG

```ts
const session = new GameSession(storage, audioPort);
session.start({ seed, classId, difficulty, mode });
session.dispatch(action);  // 返回是否受理；动画未完成时不接受新的规则输入
session.update(dt);
session.save();
session.resume();

session.state;                  // 最新规则状态
session.timeline.display;       // 当前显示快照，独立复制
session.timeline.current;       // 本批 before/after/events/animations/falls/tokens
session.timeline.busy;
session.timeline.paused = true;
// 诊断观察器；声音/视觉应使用timeline，不能使用此即时通知来抢先播放。
session.onEvents = events => {};
```

`PresentationTimeline.enqueue(before, after, events)`按动作到达顺序缓存快照与事件。每个动画独立维护 `elapsed`/`done`，当前批完成才提交显示快照；没有动画的批次仍按 FIFO 完成。下落使用该批 after 中的最终格子载荷，避免已复用槽位错误地当作永久实体ID。`EffectQueued` 缓存来源，`EffectConsumed` 创建显示用资源飞行；读档恢复时可从 pending 找回载荷。动画结束只提交显示快照，不重复执行 ConsumeEffect。

规则推进沿用旧调试台：**falling 的 AdvancePhase → pending[0] 的 ConsumeEffect → 其他 AdvancePhase；遇菜单立即停下等待用户。** 菜单的 SelectMenuItem/ConfirmMenu 在规则层原顺序提交，显示随后播放。UI不根据不同 token 的视觉到达速度重排规则动作。C2 原版竞态仍然未决；本卡保留确定性 FIFO 策略。

三类动画：

- `Fall`：速度初值320逻辑px/s、加速度160px/s²，先更新速度再位置，达到目标吸附并复位速度；没有硬编码180ms。
- `TokenFlight`：按原Token两段积分、动态目标、移动前距离判断、scale夹在0.2–1；没有统一飞行时长。U02用固定视觉参数（普通速度6.5×320、XP5×320、转向1.175、初始方向(.1,0)），明确是近似；没有重抽规则COSMETIC。
- `Tween`：固定秒数线性补间；`FrameSnap`：每次update固定权重0.3、阈值2px的吸附，不假称0.3秒动画。

暂停菜单/设置时仅栈顶更新，局内时间线冻结；页面隐藏时冻结屏幕栈，恢复重置rAF基准时间，避免追赶后台时间。已有声音不会重播。U04可新增 `Animation`，将对象挂到对应事件批次，在自己的renderer读取，不需要改动规则顺序。若未来要求原版COSMETIC参数，需另做引擎只增字段并锁定RNG测试；本卡未做此扩展。

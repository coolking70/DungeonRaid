### 菜单显示与操作

读取 `state.menus[0]`，`id`是动作所需的菜单ID；只能操作队首。`kind`为`level/shop/upgrade`。`candidates`是带`kind`的联合：

| candidate.kind | 载荷、名称/描述/数值来源 |
| --- | --- |
| skill | `skill:{id,level,cooldown,charge,active}`；`getNativeSkill(id).displayName.text`，`skillDescription(id)`；显示候选等级/CD，与 `state.skills` 同ID旧值比较；新加入的Quicken/Cunning修正在确认时施加 |
| stat | `id=42+stat`，`stat=0…7`；`enumData.enums.StatType`中同value的displayName；增量规则如下 |
| item | `item:{type,icon,prefixAnchor,displayPrefix,suffixIndex,stats[20]}`、`scroll:SkillState|null`；`itemName(item)`给完整名称；stats索引用`itemData.upgrades`的nativeId/displayName/description；与同type已装备项比较；卷轴名称/描述同技能 |
| upgrade | `itemType,stat,value`；`stat`是装备属性0…19而非StatType；`itemData.upgrades`给名称/描述；`value`是本次候选已计算的增量；目标装备可从state.equipment按type取得 |

属性奖励显示：0 STR+1/B+1/XP概率+5；1 DEX+1/修甲+1/盾概率+5；2 VIT+1/HP+5/药概率+5（Pretzel无HP）；3 LUK+1/治疗+1/金概率+5；4 B+2；5修甲+2；6 HP+10；7四概率各+5。基础概率各钳100，装备概率单列。换算表来自classes.json的statIncrements，证据`Initialise(StatType) @0x606a4`/`SetSkill @0x2be04`；不要把属性候选当作可装备技能。

```ts
step(state, { type: 'SelectMenuItem', menuId: menu.id, index });
step(state, { type: 'ConfirmMenu', menuId: menu.id });
// 等价确认：ChooseMenuOption { menuId, option:'confirm' }
```

已选再次点击取消；商店/强化选另一个替换当前选择；等级菜单选满两项后点击第三项不改变选择。`selected`按选择顺序保存，确认按该顺序生效。level需要2项，其余1项；shop数组只有3项，没有可点第四项。三者skip均报错。事件：`MenuRequested`含候选快照，`MenuSelectionChanged`含选择索引，`MenuClosed`通知关闭；状态是显示依据。

### 技能与卷轴

- 手动：`step(state,{type:'CastSkill',slot,source:'manual'})`，slot为已装备0…3。
- UI使能直接用 `canCastSkill(state,slot)`：输入阶段、无正在拖的链、技能存在、charge严格等于cooldown、目标门槛成立。`canActivate(state,id)`仅查目标，不能单独当按钮使能条件。
- 成功不直接EndOfTurn；若产生token/移动，继续沿原有 `AdvancePhase/ConsumeEffect` 协议推进，最后返回input；Enchant暂停于menu。通过`SkillCast {id,source}`显示日志。
- 购买确认自动先换装/UpdateStats再施放附带卷轴，不装备卷轴、不触发Dragonkin手动钩子。通常UI只需ConfirmMenu。
- `CastSkill {source:'scroll',slot}`作为显式购买并施放入口时，slot指队首shop菜单的候选索引，必须已选中该带卷轴候选；效果等价ConfirmMenu。不能用这个来源免费施放已装备技能。
- I1：非豁免卷轴需 `EngineOptions.scrollFilter='supplied-native-fixture'` 和每次 `step` 的 `hooks.scrollNativeWord(state,skillId)`；返回值是原生`Game+c358+4*skillId`的整数word。缺失/非整数/空最终池明确报错。请勿把模拟的全零合成fixture当作正式兼容策略。

### 职业与奖杯

`NewGame`追加可选`character:ClassConfiguration`（classId需匹配动作classId；race、四perk槽、四flaw槽、20个replacementSkills）；替换槽255表示回退基础vector。未传时保持原默认职业。输入只做结构检查，不代替编辑器限制；编辑器可用`isPerkSlotUnlocked`、`canChangeRace`、`replacementSkillsAllowed`、`validateConfiguration`、`getSkillPool`/`isSkillUnlocked`。

`step(state,{type:'ClaimTrophy',slot})`中slot为行优先棋盘索引`y*6+x`。要求input阶段、该格确为未冻结/未消除奖杯。事件`ClassLevelChanged {classId,before,after}`可显示升级/解锁；`TrophyClaimed {slot,classId|null}`表示已领取（全职业满级时null）。更新后的`state.classLevels`立即影响后续解锁池和奖杯资格。领取补盘后按现有阶段协议返回input，不产生一次普通敌攻。

## 发现的规格问题与未决问题

1. **Validate并不实现规格05文字所称的等级替换数量裁剪。** `CharacterClass::Validate @0x36390`调用`GetReplacementSkillCount @0x36364`，后者仅数实际非255槽数，没有调用`GetReplacementSkillsAllowed @0x35dc0`。随后对每个非255项减计数，按这段代码不会减到负数。实现保留原生行为；另提供等级允许数量查询供编辑器约束。P30的资格数值仍完整通过。未修改规格文件。
2. **法力创建无目标与到达时槽失效不同。** `GetSpecialTarget @0x4b254`返回槽号，`Token::InitialiseFromTile @0x653d0`写Token+0x98，负值直接隐藏。`RemoveSkill @0x24eec`压缩技能槽，不重写已创建token。`AddResource @0x32210`在已绑定槽号超出当前技能数时落入普通治疗分支。实现不重抽、不按技能对象重绑，测试覆盖两种边界。03/P31的“无目标不治疗”适用于创建时，不能扩大为迟到token的所有异常情况。
3. **Rune先于有效链长度判断。** `ProcessInput @0x330c0`先`ProcessRune(true)`，再检查有效节点>2并进入`MatchTiles`；后者清本链各类型计数。实现遵守该顺序。新增菱形两箭/两忽略金币fixture：有效节点仅2仍收中心，不推进敌方回合；Rune本身不补盘，匹配标记保留到后续正常补盘。这补充了03中“函数本身不MoveMatchedTiles”的阶段含义。
4. **三种奖励菜单均无跳过。** `ProcessInput @0x41d54`确认门槛仅为level双选/其余单选，未发现独立skip分支。原T04测试/调试接口的跳过仅是占位；本卡按伪C拒绝。`ui/`未修改，等待表现层接入。
5. **I1仍未决。** 保留原始word回调和10%豁免；没有推导“排除已持有技能”。空最终池时原生会走空vector索引，移植明确报错，未复刻非法内存访问。全零模拟fixture仅用于测试。
6. B1/B2、C2/C3/C4等原版运行对照边界继续保留。菜单/技能已知分支有单测，仍未获得原版逐帧token到达轨迹与全部种族/特殊敌人/技能组合golden trace。没有声称这批测试关闭这些未决项。

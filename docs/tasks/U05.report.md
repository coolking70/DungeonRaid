# U05 结算节奏、跳过与敌人数值核查报告

日期：2026-10-16。已阅读AGENTS.md及任务卡所有前置材料。代码、测试、原生补证、浏览器测量和截图已交付；没有修改规则引擎、reverse、APK、美术、字体、翻译目录或音频实现，没有安装依赖、commit或推送。

## 结算耗时与瓶颈

脚本：[tools/u05-browser.mjs](../../tools/u05-browser.mjs)。同一seed12345、Normal/Classic、无优缺点、确定性棋盘，真实pointer连线；以浏览器`advanceTime(1000/60)`逐帧计时，终点为表现队列清空（input／menu）。这张表是**60Hz表现时间**，不是脚本进程耗时；JSON另存harnessWallMs。修改前记录在修改前代码上实测留存，不能在新代码上用`before`参数重建旧实现。

| 用例 | 修改前 | 原版速度（默认） | 快速 | 跳过后表现完成 |
| --- | ---: | ---: | ---: | ---: |
| 3格金币 | 1883ms | 600ms | 300ms | ≤1帧 |
| 8格金币 | 4883ms | 633ms | 317ms | ≤1帧 |
| 15格金币 | 8633ms | 633ms | 317ms | ≤1帧 |
| 25格金币（含额外token） | 14317ms | 717ms | 350ms | ≤1帧 |
| 两剑＋一敌、击杀 | 900ms | 733ms | 367ms | ≤1帧 |
| 金币99开始、满条至菜单前 | 717ms | 550ms | 267ms | ≤1帧，菜单直接展开且可选 |

证据：[U05.before.json](U05.before.json)、[U05.after.json](U05.after.json)。改前最大并发token数为1；改后3/8/15/25格分别为3/8/15/27。额外token来自现有规则抽样，不是UI复制。各用例跳过handler耗时见JSON，均小于1ms；另用**真实requestAnimationFrame与performance.now**复测25格：正常约720ms，点击跳过约1.3ms，低于100ms目标。这是本机Chromium结果，不是Android真机性能保证。

根因：`GameSession.drain()`本来就同步按fall→FIFO pending→phase推进，没有固定sleep；`PresentationTimeline`却在每个`EffectConsumed`上创建独立TokenFlight，每批飞完才推进下一批。另外每个无token／fall但含visual的批次又强加.3s阻塞；标签自身还可以存活1s。瓶颈在表现串行，不在规则计算。

默认保留原版速度，因为并发后25格只需约.72秒，已消除线性等待；快速模式以2倍表现dt进一步压缩。未新增按序号递减的发射间隔：原生证据已经足以解释并修复慢的问题。

## 原生节奏与实现

补证已写入[11-animation.md](../spec/11-animation.md)。`MatchTiles @0x31bcc`、`AddToken @0x2a934`在一轮调用里立即创建token；`Game::Process @0x339ac`遍历全部活动token。没有找到批内固定错开发射的计时器。`Token::Process @0x65200`的u+=a·dt为单颗加速，起点、方向和速度随机值造成到达错落。

实现调整：

- 在`EffectQueued`帧创建并启动整批token，使用原已消费的cosmetic样本，不追加RNG；飞行与下落并行。
- `EffectConsumed`帧等待已存在的token；即使后面的token先飞完，资源显示仍按FIFO提交。存档恢复缺少creation帧时使用已有确定性回退。
- 飘字、粒子不再给规则阶段附加.3s等待。敌攻合并事件以原flare的1/4.5秒作为反馈门槛；详见已知差异。
- `GameSession.skip()`沿用同一drain并完成所有表现帧；清除飞行、飘字、粒子，按顺序提交显示快照；有菜单就停，不选择、不确认菜单。菜单跳过展开动画，下一帧即可选择。
- 同一轮update／skip内同一个音效ID最多播放一次。跳过按下优先于技能、HUD按钮和棋盘输入；相应抬起也吞掉，不会顺带使用技能、打开菜单或选格。
- 设置添加「动画速度：原版／快速」，独立持久化，不进入RunState。

## 敌人数值结论与根因

完整原生坐标、颜色、字号、条件、刷新调用点见[10-ui-screens.md](../spec/10-ui-screens.md)的U05补证。

- 原版右侧从上到下为**攻击白色、防御淡紫、生命红色**；防御为0也显示。原实现把攻击放左上、生命居中，而且隐藏0防御，与原版不符。现已改为原生锚点，并按数值宽度将敌人图像左移3.2／6.4px。
- `GetAttack()`可能因Elf中毒效果不同于存储attack，现视图也用规则的有效攻击函数。
- 倒计时属于Golden／Kamikaze／Unstable／Disarming等特殊能力，并非每只骷髅都有“距下次攻击”。命匣原版不画四种数字，已去掉旧版额外的↻数字。
- `timeline.display`旧版在非下落visual帧完成前保持before；确有暂时滞后，但**未发现结算结束后数字永久冻结**。现在`boardState()`统一取当前事件after棋盘，生命／防御／倒计时／毒槽与该阶段规则同步，保持移动槽位和数字对应。HUD资源依然按到达队列递交，避免提前显示未来奖励。
- 旧通用`text()`的12px倍数量化会把10、11、14px请求都变成12px。敌人数字改用13px数字字体、倒计时19px和描边；不改全站字体，也不冒充原版字体。
- 毒伤原版没有额外静态Label，主要是变色和飘字。Web增加绿色`P<下回合伤害>`；详情展示三个毒槽，这是明确的移植增强。
- 连线中的非致死损失／致死叉预览原来已有，本次保留、截图验证，并让提交后的连线、调暗、伤害提示随当前after快照立即消失。
- Tooltip补齐名称、说明、有效攻击、防御、当前／最大生命、能力倒计时、未来三回合毒伤。支持单击和≥.45秒长按。

实际规则操作的视图单测覆盖：非致死攻击、毒伤、Kamikaze倒计时3→2、Healer回血、Vengeful加攻、Vampire回血；另测Elf有效攻击和命匣显示条件。并非只手改视图字段的镜像测试。浏览器中同一敌人生命30→23，带毒时进一步23→21，倒计时3→2；伤害开始100ms截图已显示23。

## 100回合成长核查

脚本：[tools/u05-growth.mjs](../../tools/u05-growth.mjs)，结果：[U05.growth.json](U05.growth.json)。固定seed12345，Normal/Classic，真实走100回合。只在开局将HP上限及当前HP设100000以确保存活；之后不改规则状态。采样新生移动槽，并在完成第10/50/100回合时，在私有副本上调用100次GenerateStats，不推进实际对局RNG。

| 已完成回合 | 该回合过程中观察到的新生普通骷髅：攻击／防御／生命 | 在准确turn值上独立生成100只的范围 |
| --- | --- | --- |
| 10 | 1／0／4 | 1／0／4 |
| 50 | 1／0–1／4 | 1／1／4 |
| 100 | 1／2／4–6 | 1／2／5–6 |

回合中的新生事件可能在EndOfTurn自增前产生，因此JSON保留原始turn=9/49/99，不把它们混称精确q=10/50/100的GenerateStats结果。过程中还可能有技能生成或属性覆盖，精确曲线看私有副本采样。

Normal曲线来源`Tile::GenerateStats @0x63098`及01号规格：attack=max(1,RandI(q/65,q/55))，defence=max(0,RandI(q/50,q/40))，health=max(4,RandI(q/20,q/15))，整数截断；前100回合没有后期加速。故前几十回合经常都是1攻击、4生命，甚至100回合攻击仍为1是正确结果，不能为“看起来变化”擅自改增长规则。

## 已知差异与未决问题

1. 原生会按实际飞行到达调用AddResource，既有引擎按显式FIFO。U05保持引擎顺序／RNG／菜单边界，没有借此解决C2逆向未决。
2. “原版”速度表示token／fall使用原积分参数；敌攻仍为合并事件反馈，未精确重放原生stage1–7的每段遮罩、反击透明度、伤害飞行。各段已知时序及重叠证据已补到11号规格，不能称整个动画系统完全保真。
3. 数字使用系统字体，普通/倒计时字号为手机可读性适配；绿色毒数、完整毒槽Tooltip、普通骷髅简短说明、快速2倍为移植增强。原毒色插值RGB端点仍未完全恢复。
4. U04已有的特殊飞行轨迹、粒子几何、部分飘字定位差异仍在；本卡修复的是并发、输入跳过和数值同步。飘字可以在可输入后继续淡出，不再阻塞下一步操作。
5. 耗时来自本机浏览器，手机截图是移动视口和触控仿真；未进行Android真机性能／听感测试。

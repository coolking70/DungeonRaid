# L01 中英双语文本与像素字体子集

**执行者**：Codex（gpt-6-astra）
**前置阅读**：`AGENTS.md`、`docs/P3-PLAN.md`、`docs/spec/10-ui-screens.md`、`data/ui-strings.json`、`data/enums.json`、`data/items.json`、`data/classes.json`。

## 目标

建立完整的 i18n 数据：默认中文，可切换英文。英文直接沿用原版字符串，中文为新翻译。同时为中文和英文界面生成像素字体的子集。

## 输入

- `data/ui-strings.json`：704 条本地字符串，另有 837 条对已有数据的引用。
- `data/enums.json`、`items.json`、`classes.json` 中的显示名和描述，覆盖技能、装备属性、名称池、敌人、职业、种族、优缺点、成就、难度、模式等。
- **字体**：Claude 已经下载好 `fonts/vendor/fusion-pixel-12px-proportional-zh_hans.otf.woff2`，即 Fusion Pixel Font 2026.09.25，许可证见同目录的 `OFL.txt` 与 `LICENSES/`，均为 SIL OFL 1.1，没有保留字体名。不要另行下载其他字体。

## 要做的事

1. **`data/i18n/en.json` 与 `data/i18n/zh.json`**
   - 键采用统一命名，例如 `ui.menu.newGame`、`skill.12.name`、`skill.12.desc`、`enemy.4.desc`、`item.prefix.37`。
   - 每个键注明来源，指向 `ui-strings` 的 id 或数据文件中的路径。
   - 去重：同一原文在多处使用时，可以共用一个键，但必须保留来源列表。
   - 带占位符的格式串（数字、名称拼接等）统一改为命名占位，例如 `{value}`，并注明原版格式。
   - 原版是动态拼接的地方（例如装备名称 = 前缀 + 名词），说明中文的拼接规则，比如前缀和名词的语序。
2. **术语表 `docs/i18n-glossary.md`**
   - 统一游戏术语的中文译名：骷髅 / 敌人、护甲、强化、命匣、奖杯、连线等，以及 32 种敌人、42 个技能、10 个职业、10 个种族、20 个优缺点的译名。
   - 风格偏向简洁的游戏用语，同时保留原文的幽默。
3. **校验 `tools/i18n/check.mjs`**
   - 两种语言的键集合完全一致；
   - 占位符一一对应；
   - 中文没有遗漏或残留的英文（专有名词白名单除外）；
   - 按 `ui-layout.json` 的版面长度上限估算是否溢出，以 12px 像素字体的宽度计算，超出的列出清单。
4. **字体子集**
   - 编写 `tools/i18n/subset-font.py`，使用 fontTools 的 pyftsubset，本机已装 fonttools 和 brotli。
   - 收集 `zh.json`、`en.json` 以及界面固定符号的全部字符，从 vendor 字体生成 `fonts/fusion-pixel-12-subset.woff2`。
   - 子集文件中保留字体的版权与许可信息，并把 `OFL.txt` 和 `LICENSES/` 复制到 `fonts/`。
   - 在报告中写明子集的字数和文件大小，目标是比原文件 666 KB 小得多。
5. **单元测试 `test/i18n.test.ts`**
   - 调用上面的检查逻辑；
   - 确认字体子集覆盖两种语言所需的全部字符：用 fontTools 预先导出 `fonts/fusion-pixel-12-subset.chars.json`，测试读取它来比较。

## 用户反馈（原话要点）

1. 和原版相比，每一步操作的结算都太慢，连消很多格时尤其要等好一会。这个过程应当**越来越快**。玩家等不及点屏幕时，应该**立刻让所有飞行动画同时播放、立刻结算**。
2. 敌人图像上的数字**似乎毫无变化**，不清楚是 bug 还是别的问题。用户印象中，原版能看到敌人正确的生命值、距下次攻击的回合数等信息。

## 第一部分：结算节奏与点击跳过

1. **先测量现状**
   - 写一个浏览器自动化脚本，测量从提交连线到回到 input 阶段的耗时。
   - 测试用例：连 3、8、15、25 格，以及含击杀和资源条满（弹菜单前）的情况。
   - 找出瓶颈：token 是串行还是并发、每段等待多久、`AdvancePhase` 之间有没有固定的 sleep。
2. **对照原版**
   - 依据：11 号规格中 `Token::Process` 的加速积分（u += a·dt，速度随时间上升）、token 的发射间隔、敌人攻击段的时长。
   - 原版中，同一次结算产生的 token 是怎样错开发射、同时飞行的？以伪 C 为准还原。
   - 预期结论：长链的总时长不应随格数线性增长，后续 token 越飞越快。
3. **实现**
   - 节奏按原版还原。若原版机制本身无法单独解释用户反馈的慢，可以在原版基础上增加「越来越快」的加速（例如同批 token 的发射间隔逐渐缩短），并在报告中写明这是移植新增的手感调整。
   - **点击 / 触摸跳过**：结算动画播放期间，玩家点击屏幕任意位置时：
     - 所有尚未发射和正在飞行的 token、飘字、粒子立即快进到终点或直接完成；
     - 依次立即消费全部 pending 效果，并推进各个阶段，直到需要玩家输入为止（input、菜单或局终）。
   - **跳过只改变表现时长，不得改变规则的结算顺序**：`ConsumeEffect` 的顺序、RNG 调用与不跳过时完全一致。要写测试证明：跳过与不跳过的最终 `RunState` 和 RNG 记录逐字节相同。
   - 跳过时音效不要全部叠在一起爆音：同一音效在同一帧只播一次，或者限制并发数。
   - 设置中增加「动画速度」：原版 / 快速。默认值按测量结果来定，并说明理由。
4. **验收数据**：报告中给出改动前后各个用例的耗时表，以及跳过所需的时间（目标：点击后 100ms 内回到可输入状态）。

## 第二部分：敌人数值显示核查

1. **原版显示什么**
   - 阅读 `Tile::UpdateText`、`UpdateValues`、`RenderText`、`UpdateCountdown`、`Tile::Render` 及相关 Label 的设置。
   - 弄清原版在敌人格子上显示哪些数值（攻击、防御 / 护甲、生命、倒计时、中毒等）。
   - 每个数值的位置、颜色、字号、显示条件，以及**何时刷新**：受伤后、回合末、能力生效时、拖线预览时。
   - 结论写入 `docs/spec/10-ui-screens.md` 并附证据。
2. **现在为什么看起来不变**。排查以下几种可能，给出实证：
   - 显示快照是否滞后：`timeline.display` 和 `frame.after` 在非下落帧是否没有更新；
   - 非致死伤害后，生命值是否在画面上减少；
   - 中毒的持续伤害、Healer 回血、Vengeful 加攻、Vampire、倒计时递减，这些情况下画面是否同步更新；
   - 普通骷髅的数值是否随回合按规格成长（01 号规格 `GenerateStats` 的曲线）。用固定种子打 100 回合，统计第 10、50、100 回合的新生骷髅数值；如果始终不变就是 bug。
   - 字号是否被 `text()` 的 12px 下限量化后挤在一起看不清。
3. **修复**
   - 实时显示必须与规则状态一致。
   - 拖线时，在敌人格子上显示「本次伤害 / 致死」预览（调试台原来就有）。
   - 长按或点击敌人时，提示框显示完整信息：名称、描述、攻击、防御、生命、上限、倒计时、中毒。
   - 位置和样式以原版为准，并保证手机上清晰可读。
4. **测试**
   - 视图模型的单测：非致死攻击后，显示的生命值等于规则状态；倒计时随回合递减；中毒伤害后显示更新。
   - 浏览器截图：同一敌人受伤前后、倒计时变化、中毒状态，桌面与手机各一组。
